Foundry Agent Service: Spectrum from Declarative to Full-Code

Compare Prompt Agents, Hosted Agents, and Ephemeral Responses API alongside the 7-phase agent lifecycle.

Unified Agent Runtime

Prompt Agents

Declarative

Configured via Portal, SDK, or REST. Managed zero-container execution with built-in tools.

  • No containers, zero app code to maintain
  • Managed state storage (Threads, Runs, Files)
  • Automatic autoscaling with request volume
  • Ideal for fast prototyping & standard tasks
agent = project.agents.create_agent(...)

Hosted Agents

Full Code

Bring container image or zip file. Built with Agent Framework, LangGraph, or custom code.

  • Managed endpoint with dedicated Entra identity
  • Long-running tasks & durable state storage
  • MicroVM isolation & BYO VNet injection
  • Complex multi-agent & custom protocols
azd deploy / container image deployment

Responses API

Ephemeral / In-App

Agent instructions and tool definitions live entirely in client application code.

  • No agent resource created or managed in Azure
  • Versions alongside app git repo & pull requests
  • Full access to Foundry models, tools, and telemetry
  • Ideal for existing microservices & CI/CD
openai.responses.create(model=..., tools=...)

Preview Feature

Durable State Management for Long-Running Hosted Agents

To survive infrastructure restarts, process crashes, and human-in-the-loop approvals, long-running agents decouple state into two distinct tiers:

1. Checkpoint Index (Task Metadata):

Lightweight key-value namespace (ctx.metadata) tracking workflow step numbers, session watermarks, idempotency keys, and explicit flushes. Fast, low-latency recovery anchor.

2. Checkpoint Store (Durable State Store):

Bulk persistent storage (FoundryStateStore, Blob, Cosmos DB) holding large conversation histories, LangGraph framework checkpoints, and intermediate artifact generation.

Model Router: Dynamic Real-Time Prompt Routing

Automatic Cost & Latency Optimization

Model Router is a specialized, pre-trained neural router deployed as a single endpoint. Instead of hardcoding model choices, prompts are dynamically routed based on complexity, quality thresholds, and latency requirements.

Step 1: Input
Single Unified Request
Client calls single router deployment endpoint
Step 2: Analysis
Complexity Scoring
Prompt features, reasoning depth, token count analyzed
Step 3: Routing
Dynamic Path Selection
Route to Small/Fast vs Frontier Reasoning model
Step 4: Return
Transparent Response
Output returned with metadata & telemetry trace
Path A: Low-Complexity Prompts (e.g. 70% of traffic)
Routed to GPT-4o-mini / Phi-4 / Mistral Small. Saves up to 80% on token cost with sub-second response times.
Path B: High-Complexity & Multi-Step Reasoning
Routed to GPT-4o / DeepSeek-R1 / Claude 3.5 Sonnet. Preserves maximum reasoning accuracy for intricate coding and analysis.

Developer SDKs, APIs & Interoperability Protocols

Explore code patterns across Foundry SDK, Agent Framework, OpenAI SDK, Anthropic SDK, and MCP remote endpoints.

from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

# Connect to Foundry Project via project-scoped endpoint
project_endpoint = "https://my-foundry-resource.services.ai.azure.com/api/projects/customer-service"

project = AIProjectClient(
    endpoint=project_endpoint,
    credential=DefaultAzureCredential()
)

# Access project models and unified platform tools
openai = project.get_openai_client()
response = openai.responses.create(
    model="gpt-4o",
    input="Analyze customer warranty issue and query inventory.",
    tools=[{"type": "web_search"}, {"type": "code_interpreter"}]
)

print(response.output_text)
