The core problem

A split-brain codebase

Two unrelated styling architectures are wired into the same tree, and they disagree on colour, spacing, elevation and dark-mode strategy.

1 · Two component vocabularies

shadcn/ui primitives (Button, Card, Dialog…) style themselves from Tailwind v4 @theme tokens. In parallel, Sidebar.tsx, Header.tsx and every components/pages/*Client.tsx use hand-written semantic classes (.sidebar, .app main, .stat-grid article, .primary-btn) resolved by ~5,800 lines of global CSS. The two layers share no tokens — styles.css, pages.css and layout-fixes.css contain zero references to --card, --primary or --surface-*.

2 · The spec no longer matches the code

DESIGN.md and PRODUCT.md still describe the culturally-grounded Khata & Blackboard palette. globals.css ships a different system. The team has chosen to keep the shipped system — so the resolution is to rewrite the docs to match the code, not the reverse.

Shipped in globals.css — adopted

--primary  #14182b (near-black navy)
--coral  #FF6B57 (accent / CTA)
--background  #f8f9fc
--muted-foreground  #64748b

Formalize this into a 3-layer OKLCH system and fix its weak spots (below). Regenerate DESIGN.md from it.

Not the direction. One idea worth keeping regardless of palette: a reserved red token for marks & deductions only — see M-01.

Until the spec is rewritten, any next engineer reading DESIGN.md will "correct" the code back toward bottle green. Rewriting the docs and adding a token-lint gate is step one.

Findings · A — Architecture & CSS system

Where the debt lives

C-01Critical

Spec and code describe different design systems

src/app/globals.css : 77–197 vs DESIGN.md / PRODUCT.md front-matter

globals.css ships "Academic Daylight / Cosmic Study" (navy-black primary, slate neutrals, coral accent). DESIGN.md and PRODUCT.md still document "Khata & Blackboard" (bottle green, warm paper, reserved examiner red). Resolution: the shipped system is adopted — rewrite both docs from the shipped tokens, and add a lint gate (see Phase 7) so the next reader of DESIGN.md doesn't revert the code. Critical because the divergence actively invites regressions until closed.

C-02Critical

~5,800 lines of hand-written global CSS bypass the token layer

src/styles.css (2,120) · src/pages.css (1,593) · src/layout-fixes.css (2,087)

Semantic selectors (.sidebar nav a.active { background:#14251f }) with 644 hard-coded hex values, imported as four unscoped global sheets in layout.tsx whose cascade order is load-bearing. This is the single largest obstacle to any redesign — it cannot be re-themed via tokens.

src/app/layout.tsx import './globals.css'; import '@/styles.css'; // redefines :root --navy/--coral/--paper … import '@/pages.css'; import '@/layout-fixes.css'; // 2,087 lines, 429 ".dark" rules, 27 !important
H-01High

layout-fixes.css is a 2,087-line patch file maintaining a second dark theme by hand

src/layout-fixes.css — 429 .dark selectors, 27 !important

A file named "fixes" this large is a standing signal that the layout primitives underneath it don't work. Every dark-mode value here is a manual override of a light value elsewhere, with no shared variable between them.

H-02High

Duplicate, drifted :root token blocks

src/styles.css : 2–10

styles.css re-declares --navy, --muted, --paper, --coral, --border with its own values, shadowing globals.css. Two sources of truth for the same names guarantees the drift already visible between them.

M-01Medium

Only one semantic status colour; no reserved "mark" token

src/app/globals.css — only --destructive: #ef4444

A grading product needs --success / --warning / --destructive as distinct semantic tokens, plus — worth keeping from the old spec regardless of palette — a reserved --mark-deduction used only for score losses and the margin-rule component, so "the examiner marked this" reads differently from a generic error toast. These are aesthetic-neutral; they fit the shipped direction fine.

M-02Medium

No OKLCH; sRGB hex only

The W3C Design Tokens spec (stable, Oct 2025) and shadcn's own current defaults use OKLCH for perceptually-even ramps and reliable contrast. All ~50 tokens here are hex, so tint/shade steps are eyeballed and dark-mode lightness is inconsistent.

Findings · B — Theming mechanism

Two theme engines, neither wired cleanly

C-03Critical

Theme flash (FOUC) on every cold load

src/context/ThemeContext.tsx : 39–50

The .dark class is added inside a useEffect, i.e. after hydration. There is no blocking inline script in <head>, so dark-mode users get a full-white flash on every hard navigation. suppressHydrationWarning is set on <html> but nothing writes the class early enough for it to matter.

H-03High

Custom ThemeContext and next-themes coexist and disagree

src/context/ThemeContext.tsx (wired) · src/components/theme-provider.tsx, theme-toggle.tsx (dead) · src/components/ui/sonner.tsx (reads next-themes)

The app is themed by the custom context, but sonner.tsx calls useTheme() from next-themes — which was never initialised — so toasts always render in the default ("system") theme regardless of the user's choice. theme-provider.tsx / theme-toggle.tsx are imported nowhere.

M-03Medium

darkMode boolean threaded through props

ClientShell.tsx → Header.tsx

Theme state is passed ClientShell → Header as props and the .dark class is toggled both on document.documentElement and on the .app wrapper div. A single provider + useTheme() hook removes all of it.

Findings · C — Typography & localisation

The Bengali path is broken

C-04Critical

<html lang="bn"> is hard-coded for all users

src/app/layout.tsx : 57

Every visitor — including the English UI — is served with lang="bn", which triggers the :lang(bn) override in globals.css: --font-sans is swapped to Noto Sans Bengali and Bengali line-height is applied globally. English copy renders in the Bengali body font. The LanguageContext toggle swaps translation strings only; it never updates lang or dir. This is also an SEO / hreflang and screen-reader-pronunciation bug.

H-04High

--font-display-bn is referenced but never defined; Baloo 2 is latin-only

globals.css : 239 vs layout.tsx : 13–39

:lang(bn) { --font-heading: var(--font-display-bn) } points at a variable that layout.tsx never creates (only --font-display, --font-body, --font-mono-eyebrow, --font-body-bn exist). Bengali headings silently fall back to a system font. Separately, Baloo_2({ subsets: ['latin'] }) cannot render Bengali at all — a Bengali display face (Anek Bangla, Baloo Da 2, Hind Siliguri) is needed.

M-04Medium

15 font weights across 4 families for a stated low-bandwidth audience

layout.tsx : 13–39 · PRODUCT.md "varying internet bandwidth across divisional and rural Bangladesh"

Baloo 2 ×5, Inter ×4, Space Mono ×2, Noto Sans Bengali ×4 all load on first paint. Trim to the weights actually used (typically 2 per family) and lazy-load the Bengali faces behind the language toggle.

M-05Medium

Type scale & numeric rules live only in prose

DESIGN.md defines clamp() display sizes, a 65–75ch measure and a tabular-nums rule for all scores/timers. None are encoded as tokens or utilities, so they aren't enforced anywhere.

Findings · D — Layout, grid & responsiveness

One breakpoint, and an off-by-36px shell

H-05High

Sidebar / main offset mismatch and a single 1050px breakpoint

styles.css .sidebar { width:244px; inset:18px } vs layout-fixes.css .app main { width: calc(100% - 280px) }

244 + 18 + 18 = 280, but only if the insets are counted as gutter — the numbers are maintained independently and already disagree in the collapsed state (main width doesn't respond to .collapsed). The entire shell flips at one @media (max-width:1050px); DESIGN.md asks for distinct mobile (<640), tablet (640–1024) and desktop behaviours. There is no real tablet layout.

H-06High

Hand-built overlays instead of the Radix primitives already in the bundle

src/components/Header.tsx : 88–110, 235–270

The profile menu, notification menu and ⌘K search modal are custom: manual outside-click useEffect, manual Escape handling, a backdrop <div onClick>, no focus trap, no role/aria-expanded/aria-modal, no scroll lock. radix-ui (DropdownMenu, Dialog) and shadcn Command are already installed.

M-06Medium

Content max-width removed

src/layout-fixes.css : 1–5 — .app main { max-width: none }

Comment reads "use the full desktop canvas". On a 1440px+ monitor this produces 140+ character line lengths in rubric feedback and tutor dialogue, against DESIGN.md's explicit 1200px / 65–75ch rule.

M-07Medium

Breakpoint logic duplicated in JavaScript

Header.tsx : 158 — if (window.innerWidth <= 1050)

A JS copy of the CSS breakpoint, read once in a click handler with no resize listener and SSR-fragile. Should be a CSS-driven state or a matchMedia hook.

Findings · E — Components, a11y & config

Loose ends

C-05Critical

A localhost:8400 dev script is committed into the production layout

src/app/layout.tsx : 68–70 (committed in 2ccf61c)

<script src="http://localhost:8400/live.js?token=4de4d515…"> — an Impeccable live-preview hook. In production it is a blocked mixed-content request, a guaranteed console error, and it leaks a token. Remove it and add the marker pair to .gitignore tooling.

H-07High

Two button systems; primary role unassigned

shadcn Button (variant=default → bg-primary = black) vs .primary-btn / .landing-cta-btn (13 uses)

DESIGN.md defines two primaries — bottle green (institutional) and coral (student CTA). Neither is a button variant. The shadcn default resolves to near-black; the landing page hand-rolls its own.

H-08High

next.config.ts is empty; the marketing page is fully client-rendered

next.config.ts (no options) · src/app/page.tsx : 1 'use client'

No images config, no cacheComponents (despite AGENTS.md mandating the Cache Components model), no typedRoutes. The primary acquisition surface renders client-side for a useLanguage hook and a vanity counter, costing LCP and SEO.

M-08Medium

Non-semantic interactive elements & invisible focus

Sidebar.tsx .school (div with chevron, no button role) · <i> used as "New" badge and unread dot · globals.css --ring: #ff6b57

The user-switcher looks actionable but isn't keyboard-reachable. The coral focus ring is near-invisible on coral buttons — focus colour should contrast with the control it's on.

M-09Medium

Reduced-motion override is brittle and contested

globals.css : 244 *:not(.animate-spin):not(.animate-pulse) vs layout-fixes.css page-in / card-in / float / draw-chart keyframes on .app main > *

The global reduce rule and the "fixes" animations fight over the same elements; class-exclusion selectors are fragile. Motion should be opt-in per component and gated once, centrally.

M-10Medium

Shipped debug & fabricated data

Header.tsx : 71 console.log('Submission graded!', payload) · notifications: any[] · page.tsx : 17 useState(2892) then 2892 + count

Console noise in a realtime handler, untyped notification objects, and a hard-coded student-count base that inflates the real number on the landing page.

Keep the framework. Replace the styling layer with one token-driven system and let shadcn own every primitive.

Three-layer token model

  • Primitive — raw OKLCH ramps: --slate-50 … --slate-900, --coral-*, --emerald-*, --amber-*, --indigo-*. No component ever references these directly.
  • Semantic — intent names mapped from primitives: --background, --surface-1/2/3, --heading (= slate-950), --cta (= coral-500), --secondary-accent (= emerald-500), --success, --warning, --mark-deduction (reserved), --rule, --ring. Only these appear in @theme inline; dark-mode overrides re-declare only this layer's source vars.
  • Component — where a primitive needs a per-component exception: --btn-cta-bg, --sidebar-active-bg, --score-ring-track.

Hardening the shipped direction

Adopt "Academic Daylight / Cosmic Study" as-is in structure, but fix these before formalizing:

  • Action colour. --primary: #14182b is right for headings, flat as the only button colour on a product for teenagers. Promote coral (or introduce a green) to the primary action role; keep navy for type and --foreground.
  • Secondary accent. Coral is currently CTA + chart-1 + focus ring + wordmark. --chart-2/3/4 (mint / amber / indigo) exist but never appear in UI — pick one as a real secondary so not everything interactive is coral.
  • Dark temperature. #0b0e17 is a cool blue-black against a warm coral. Nudge the dark neutrals a few degrees warmer, or drop coral chroma slightly in dark, so they read as one set.
  • Rename the shadcn accent slot. --accent: #fff7f5 / #ff5a43 is a coral tint occupying the generic "accent" token — it collides with brand coral. Give brand coral its own name (--cta) and let --accent be a true neutral hover.
  • Status tokens. Add --success / --warning and a reserved --mark-deduction (M-01).
  • Contrast audit. Verify every text/surface pair at WCAG 2.2 — --muted-foreground #64748b on --surface-2 #f1f5f9 is the marginal one.
